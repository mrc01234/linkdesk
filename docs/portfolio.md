# 项目经历表述与补学清单

## 当前事实

LinkDesk 是基于 MIT 开源项目的 AI 辅助二次开发。本轮代码、测试和文档主要由编码助手根据约定范围完成；用户已有 Go/SQL 学习与实际数据库运行记录，但本项目的新改动仍需本人运行、阅读与复述。

不要把“仓库在自己的账号下”写成“所有功能从零独立设计实现”。上游已有短码生成、二维码、基础鉴权、CLI、点击统计和 SQLite。

## 可使用的诚实介绍

**LinkDesk 链接管理工具｜个人学习项目 / 开源二次开发**

技术栈：Go、chi、database/sql、SQLite、HTML/CSS、Docker。

> 基于开源短链服务，在 AI 辅助下扩展链接搜索、数据库分页与到期失效功能；配套补充 SQLite 集成测试、中文管理界面与部署文档。

这是当前项目事实的表述。只有自己完成下面的演示、读懂对应代码后，才建议把细节作为面试中的本人实践展开：

- 搜索与状态过滤在 SQL 层完成，COUNT 和分页查询共享读事务，使用创建时间与 ID 稳定排序。
- 增加可空的到期字段及旧库迁移，过期短链返回 410 并停止累计访问。
- 修复空列表显示与 GET 删除，覆盖空结果、边界参数、并发冲突和认证相关测试。

不要写“精通 MySQL”“高并发平台”“独立设计完整系统”或没有测量依据的性能数据。本项目数据库是 SQLite，不是 MySQL。

## 投递前最低准备：约两个学习时段

这不是补完全部数据库课程，只需围绕现成项目完成：

1. 自己启动一次，创建 / 搜索 / 翻页 / 删除，停止并重启确认持久化。
2. 沿 handler → service → database 找到搜索分页代码，说清查询参数与 SQL 如何对应。
3. 能解释：为什么主键还不够限制短码重复，为什么过期返回 410，为什么不能用 GET 删除，为什么总数和列表放进读事务。
4. 自己做一个小变更，例如把默认每页 10 条改成 20 条，并检查页面与 API 都一致。

如果暂时讲不清，可以先公开仓库并在简历里写“学习项目”，同时继续补这几项；不要包装独立贡献。

## 后续按缺口学习

优先理解本项目里的参数化 SQL、约束、分页、迁移、错误处理、HTTP 和 Git。MySQL 专项、Redis、微服务与多租户等以后根据岗位和实际需求决定，不为堆技术名词加入。
